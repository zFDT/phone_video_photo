# 帧遇统一整理媒体预览设计规格

## 目标

让用户在“统一整理”页面直接看到待整理媒体的实际画面，并在删除前安全完成浏览、比较、保留项调整和删除选择。

本阶段采用已经确认的组合方案：整理列表采用 C“自适应组卡片”，预览采用 A+“App 内单图全屏预览 + 系统打开”。

## 范围

本阶段包含图片和视频缩略图、重复/相似媒体的组内横向卡片、低质量/截图/录屏等单项分类的双列网格、App 内图片全屏预览与视频基础播放、系统应用打开原媒体，以及从预览页调整保留项和删除选择。

本阶段不包含永久缩略图磁盘缓存、修改或转码损坏媒体、预览页直接删除、进程终止后持久化未确认选择、新增图片加载或播放器依赖，以及图片编辑或视频剪辑。

批量分析错误项的诊断、分类、重试策略和修复属于独立任务，不纳入本媒体预览规格；本阶段只保证分析失败本身不会生成删除建议。该独立任务在媒体预览实现计划之后继续推进。

## 现状与问题

当前 `OrganizerScreen` 将每个媒体渲染为 Checkbox、文件名和状态文字。`OrganizationMediaItem` 已包含 URI、大小和修改时间，但没有把 MIME、分辨率、时长、HDR 和拍摄时间传给 UI，也没有缩略图或通用媒体预览入口。

用户因此无法在整理页判断照片内容、模糊程度、构图差异或视频内容，尤其不适合重复和相似媒体的人工确认。

## 交互设计

### 自适应整理列表

`EXACT_DUPLICATE` 和 `SIMILAR_MEDIA` 使用组卡片：

- 组标题显示类型、媒体数量和预计可释放空间；相似组显示置信度，精确重复组显示“内容完全相同”。
- 组内媒体横向排列，尽量让建议保留项与待删除项处于同一视野。
- 卡片主体是缩略图；文件名、大小和关键分辨率作为次要信息。
- “建议保留”“已选删除”“视频”“HDR”“无法预览”等状态叠加在缩略图上。
- 建议保留项被锁定，不允许同时勾选删除。

`LOW_QUALITY`、`SCREENSHOT`、`SCREEN_RECORDING` 使用双列媒体网格。`VIDEO_HIGHLIGHT` 显示视频缩略图，并保留“查看精彩候选帧”入口。

页面底部继续使用现有的“选择当前可删项”和“确认删除”操作，不在卡片上提供直接删除。

### A+ 全屏预览

点击媒体缩略图进入 App 内全屏预览：

- 图片支持适屏显示、双指缩放和同组左右切换。
- 页面显示当前位置、文件名、分辨率、大小、拍摄时间和 HDR 状态。
- 视频复用现有 Media3 依赖提供基础播放，并显示时长和分辨率。
- 右上角始终提供“系统打开”，用于 HyperOS 相册、动态照片、特殊 HDR 或系统播放器。
- 返回后保持原筛选、原滚动位置和本次会话中的勾选状态。

重复和相似筛选只在当前组内左右切换。低质量、截图、录屏和视频精彩等单项分类按当前筛选结果的稳定显示顺序连续切换，不跨筛选类型。

预览页允许执行两种会话内操作：

- “设为保留”：仅适用于重复或相似组。新保留项立即锁定并从删除选择中移除，旧保留项恢复为可选择状态。
- “选择删除 / 取消删除”：只更新统一整理当前会话的选择集合。

以上操作均不直接删除媒体。真正删除仍需返回整理页、点击底部确认，并经过现有删除安全校验和 Android 系统回收站授权。

## 数据设计

不修改 Room schema。现有 `MediaAssetEntity` 已提供 URI、MIME、拍摄时间、时长、分辨率、大小、HDR 和修改时间。

`OrganizationMediaItem` 增加对应的只读展示字段。`OrganizerRepository` 在建立整理组时一次性完成映射，UI 不为每张卡片反查数据库。

保留项覆盖只存在于当前 `OrganizerScreen` 会话状态中。Compose 配置变化和进入预览不会重置状态；用户明确退出统一整理页面或进程终止后重置为推荐引擎的安全默认值。构建删除计划时使用当前人工保留项，而不是始终使用推荐引擎最初的 `suggestedKeepId`，且不会自动继续任何删除操作。

## 组件设计

### `OrganizerThumbnailLoader`

- 使用 `ContentResolver.loadThumbnail()` 按目标尺寸读取图片或视频缩略图。
- 在 IO dispatcher 中加载，Compose 条目离屏或 URI 变化时取消请求。
- 使用有明确容量上限的小型内存 LRU，缓存键包含 URI、媒体修改时间和目标尺寸。
- 返回成功、媒体不可用、权限拒绝、解码失败四类结果。
- 不建立永久磁盘缓存，不改写原媒体。

### `OrganizationGroupCard` 与 `OrganizationMediaCard`

- 根据筛选类型选择横向组卡片或双列网格。
- 展示缩略图、关键元数据、保留和删除状态。
- 将点击预览、切换删除选择和设置保留通过回调传给页面状态层。
- 不读取数据库，不执行删除。

### `OrganizerMediaPreview`

- 接收当前组、当前媒体和选择状态。
- 图片按屏幕所需尺寸解码，不把超大原图完整常驻内存。首版支持 1× 至 4× 视觉缩放。
- 视频使用 Media3 播放，离开预览时释放播放器。
- 提供同组切换、缩放、元数据显示和系统打开。
- 通过回调更新当前会话的保留项和删除选择。

### 系统打开

使用 `Intent.ACTION_VIEW` 和媒体 MIME，附带 `FLAG_GRANT_READ_URI_PERMISSION`。Intent 必须通过受控异常处理确认系统存在可用处理器。失败时留在当前预览页并显示错误，不清除用户选择。

## 状态与数据流

```text
Room 媒体与分析结果
        ↓
OrganizerRepository 映射展示元数据
        ↓
OrganizerScreen 会话状态
  ├─ 当前筛选与滚动状态
  ├─ 当前人工保留项
  └─ 当前删除选择
        ↓
自适应组卡片 / 双列网格
        ↓ 点击媒体
OrganizerMediaPreview
  ├─ 按需加载图片或播放视频
  ├─ 系统打开兜底
  └─ 更新会话内保留/删除选择
        ↓ 返回
现有删除计划、二次确认和系统回收站授权
```

## 错误处理与安全规则

- 缩略图加载失败时显示占位，不自动勾选删除。
- 全屏预览失败时显示失败类别和“系统打开”入口。
- 权限丢失、媒体已移除或云端内容暂不可读时，不把媒体视为低质量或损坏。
- 解码失败不触发转码、覆盖、删除或自动重试风暴。
- 系统无可用查看器时显示错误并保留当前页面状态。
- 人工设置的新保留项必须属于当前重复或相似组。
- 同一组始终至少保留一项；保留项永远不进入删除计划。
- 删除前继续复用 live MediaStore 元数据复验、精确重复 SHA-256 复验和系统回收站授权。
- 批量分析失败工作项与整理建议分开显示；仅凭分析失败不得产生自动删除建议。

## 性能与内存约束

- 列表使用 Compose lazy 容器，只加载可见范围附近的缩略图。
- 缩略图请求尺寸与卡片像素尺寸匹配，禁止为列表卡片解码原始分辨率图片。
- 内存缓存设置字节上限，失败结果可在当前会话短暂缓存，避免滚动时反复解码。
- 全屏图片按设备显示区域约 2× 的目标尺寸采样，同时限制在 8MP 以内；首版不会在继续放大时渐进加载更高分辨率。超过采样精度的像素级检查、完整 HDR 和动态照片效果通过“系统打开”完成。
- 视频播放器在切换媒体或退出预览时释放。

## 测试与验收

### JVM 测试

- Repository 完整映射媒体展示字段。
- 人工保留项切换后，旧保留项可选、新保留项锁定。
- 删除计划排除当前人工保留项。
- 预览索引切换保持组边界。
- 单项分类预览按当前筛选结果切换且不跨筛选。
- 预览缩放范围固定为 1× 至 4×，高分辨率解码遵守 8MP 上限。
- 缩略图缓存键包含 URI、修改时间和目标尺寸。
- 加载错误映射为稳定的用户可见类型。
- 失败媒体不会被默认选中删除。

### Android / Compose 验证

- `ContentResolver.loadThumbnail()` 可加载本地图片与视频。
- 损坏图片、权限拒绝和已删除 URI 显示正确占位。
- `ACTION_VIEW` 携带只读 URI 权限，无法处理时不崩溃。
- Media3 播放器进入、切换和退出时生命周期正确。

### Redmi K70 Pro 真机验收

- 完全重复和相似组可同屏看到实际缩略图。
- 截图、低质量和录屏分类使用双列网格流畅滚动。
- 图片可全屏查看、缩放、左右切换并返回原位置。
- 视频可基础播放，演唱会长视频进入和退出无崩溃。
- “系统打开”可进入 HyperOS 相册或播放器，并返回整理页。
- 修改保留项后，删除确认中不会包含新保留项。
- 损坏媒体显示占位，不自动选择、不修改原文件。
- 连续浏览大量媒体时无明显持续内存增长或 OOM。

## 完成标准

- 用户无需依赖文件名即可识别整理项。
- 重复和相似媒体可在组内快速比较。
- 图片和视频均有 App 内预览及系统打开兜底。
- 任意加载或预览错误均不会导致误删、崩溃或原文件改写。
- 所有新增行为有相应自动化测试，并通过 Redmi K70 Pro 真机验收。

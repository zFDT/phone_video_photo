# 帧遇批量媒体分析管线设计规格

## 目标

在现有媒体索引、视频精彩帧、导出和相册整理基础上，建立一条完全本地、可批量运行、可暂停恢复的图片与视频分析管线。

管线需要满足：

- 扫描整个系统相册后，能够批量分析图片和视频。
- 应用进程被杀死、设备重启或任务主动暂停后，从最近确认的阶段继续。
- 分类、目标检测、相似度、画质评分和重复检测各自独立，可按模型版本增量重算。
- 批量分析完成后统一生成整理建议，不自动删除媒体。
- 用户人工确认前可以预览、筛选和导出原媒体或视频精彩帧。
- 默认不依赖网络，不上传媒体、向量、人脸和位置数据。

## 非目标

- 不使用生成式大模型作为全库第一层分析器。
- 不根据单个模型标签直接决定删除。
- 不逐帧分析完整长视频。
- 不复制或改写原始媒体。
- 不在本阶段训练演唱会专用模型。
- 不在本阶段执行 Redmi K70 Pro 真机性能和相册兼容性验收。

### 模型职责

#### EfficientNet-Lite2

- 对完整图片或视频采样帧生成 ImageNet 语义标签。
- 每个输入最多保存前 5 个标签和置信度。
- 标签用于相册筛选、目标检测触发和视频语义聚合。
- ImageNet 标签不直接映射为删除建议，也不用于判断“精彩”或“劣质”。

#### EfficientDet-Lite2

- 输出目标类别、置信度和边界框。
- 用于主体数量、主体面积、人物裁切、多主体分布和构图评分。
- 不用于票据 OCR、条码内容和停车位编号识别。
- 不对所有视频采样帧运行，只处理分类不确定、主体相关或已进入精彩候选的帧。

#### MobileNetV3 Small Embedder

- 为图片和视频代表帧生成 L2 归一化向量。
- 用于相似照片、连拍、相似视频片段和候选帧聚类。
- 感知哈希作为无模型兜底和第一层近似过滤。
- 向量余弦相似度只生成候选组，不能单独触发删除。

#### ML Kit 与确定性规则

- ML Kit Face Detection 提供人脸框、头部角度、眼睛睁开和微笑概率。
- 现有规则评分提供清晰度、曝光、黑帧、重复帧和场景变化。
- MediaStore 元数据继续优先识别截图、录屏、超短视频和文件类型。
- 票据、证件、条码和停车位的准确分类依赖 OCR 与条码扫描；在新增对应依赖前，仅保留候选入口，不伪装为已识别。

## 分层分析流程

```text
MediaStore 索引
        ↓
元数据预分类
        ↓
精确内容哈希
        ↓
图片解码 / 视频分层采样
        ↓
质量规则 + EfficientNet-Lite2 + MobileNetV3 Embedder
        ↓
条件触发 Face Detection / EfficientDet-Lite2
        ↓
视频级标签聚合与精彩候选
        ↓
完全重复、感知哈希和向量聚类
        ↓
整理建议与人工确认
        ↓
导出或移入系统回收站
```

### 图片处理

每张图片执行：

1. 读取 MediaStore 元数据。
2. 计算分块 SHA-256。
3. 解码受限尺寸的分析 Bitmap，并根据 EXIF 方向归一化。
4. 计算基础画质分数和感知哈希。
5. 运行 EfficientNet-Lite2。
6. 运行 MobileNetV3 Embedder。
7. 根据标签、人脸线索和分类置信度决定是否运行人脸与目标检测。
8. 保存阶段结果并释放 Bitmap。

原始分辨率只在用户导出或放大预览时读取。

### 视频处理

视频沿用现有分层采样和 Room 断点：

1. 普通模式使用 1 FPS 粗采样，演唱会模式使用 2 FPS 粗采样。
2. 每个粗采样帧运行画质规则、整图分类和向量分析。
3. 场景变化、动作变化、音频峰值或高质量区间进入 5～10 FPS 重点采样。
4. 精彩候选区间最多提升到 15～30 FPS。
5. Face Detection 和 EfficientDet-Lite2 只运行在重点区间与候选帧。
6. 每处理一帧保存下一时间戳、阶段、模型版本和累计数量。
7. 视频级标签按出现次数、最高置信度和覆盖时长聚合，避免单帧误判代表整个视频。

MediaPipe `VIDEO` 模式要求递增时间戳。任务串行解码，模型推理始终在后台线程执行。

## 条件目标检测

以下任一条件命中时运行 EfficientDet-Lite2：

- EfficientNet 前两名置信度差小于 `0.10`。
- EfficientNet 最高置信度低于 `0.45`。
- 标签属于人物、动物、车辆、乐器或演出相关映射。
- 图片被规则或用户标记为高价值候选。
- 视频帧进入重点采样或精彩候选阶段。

普通视频粗采样帧不默认运行目标检测。该规则降低长视频分析耗时，同时保留主体和构图信息。

阈值保存在分析策略版本中；修改阈值只重算目标检测触发和推荐阶段，不重复计算内容哈希。

## 质量与整理建议

### 质量分数

质量评分由确定性特征组成：

- 清晰度和运动模糊。
- 曝光、黑场和高光裁切。
- 相邻帧重复度。
- 主体面积和主体裁切。
- 人脸角度、睁眼和表情。
- 构图分布。
- 场景变化和音频峰值。

分类标签只调节不同场景的权重。例如演唱会降低微笑权重，提高主体清晰度、动作、灯光变化和音频峰值权重。

### 推荐置信等级

- 高置信：SHA-256 完全相同。建议保留拍摄时间更早、分辨率更高或文件更完整的一项。
- 中置信：感知哈希和向量同时相似，并位于同一时间窗口。展示相似组供人工比较。
- 低置信：单张质量较差、分类不确定或仅单一相似算法命中。只作为筛选标签，不默认勾选。

建议引擎不会自动删除任何文件。建议保留项默认锁定，用户显式解锁后才能选择。

## 批量任务与断点恢复

### 数据结构

新增逻辑实体：

- `AnalysisBatch`：一次全库或用户选定范围的批量分析。
- `AnalysisWorkItem`：一个媒体在一个分析阶段的工作项。
- `MediaClassification`：模型标签、置信度和模型 SHA。
- `MediaDetection`：目标框、类别、置信度和帧时间。
- `MediaFeatureReference`：向量维度、缓存路径和模型 SHA。
- `MediaQualityResult`：质量分项、总分和算法版本。
- `OrganizationRecommendation`：推荐类型、置信等级、分组和建议保留项。

每个工作项使用 `(batchId, mediaId, stage, analyzerVersion)` 作为幂等键。

### 状态机

```text
PENDING → RUNNING → COMPLETED
              ├─→ PAUSED → PENDING
              ├─→ RETRYABLE_FAILED → PENDING
              ├─→ PERMANENT_FAILED
              └─→ CANCELLED
```

图片在每个阶段完成后提交事务。视频额外保存区间索引和下一时间戳。

WorkManager 使用唯一串行工作链，避免多个大视频同时解码。批次取消只停止未完成工作项，不删除已完成结果。重新启动应用后从 Room 查询未完成项并恢复队列。

### 模型升级

结果记录模型 SHA 和分析策略版本：

- 模型 SHA 未变化时复用分类、检测或向量结果。
- 更换分类模型只失效分类和依赖分类的推荐。
- 更换 Embedder 只失效向量和相似分组。
- 更换质量权重只重算质量汇总，不重新解码可复用特征。

## 特征缓存

向量使用应用私有目录：

```text
files/features/<model-sha>/<media-id>.f32
```

Room 只保存路径、维度、校验信息和访问时间，避免数据库被大向量撑大。缓存删除后可以从原媒体重建。

缩略图、感知哈希和标签结果分别管理。缓存清理不得删除：

- MediaStore 原始 URI。
- 媒体索引。
- 用户选择和删除确认记录。
- 已发布到系统相册的导出文件。

## 批量交互

批量分析页面显示：

- 批次范围和创建时间。
- 当前阶段。
- 已完成、排队、失败和跳过数量。
- 当前媒体和视频时间进度。
- 暂停、继续、取消和重试失败项。
- 预计剩余工作量，不承诺精确完成时间。

分析完成后进入统一人工确认页，可按以下条件筛选：

- 完全重复。
- 相似组。
- 低质量。
- 截图、录屏和超短视频。
- 图片或视频语义标签。
- 视频精彩候选。

删除前展示数量、预计释放空间和建议保留项。确认后使用系统回收站。删除失败按 URI 单独报告。

## 导出

现有导出能力继续保留：

- 图片候选可导出 JPEG 或 WebP。
- 视频精彩候选可导出静态图、GIF、MP4 和 Motion Photo。
- 导出前可以选择封面、时间窗口和裁切。
- 导出结果复制用户允许的拍摄时间、方向和位置元数据。

批量分析结果只引用原媒体和候选时间点，不预生成大量导出文件。

## LiteRT-LM 边界

LiteRT-LM 不进入首轮全库分析管线。原因：

- 生成式输出不适合直接参与删除安全决策。
- 单项推理成本和内存显著高于视觉任务模型。
- 无法替代稳定的向量、内容哈希和确定性质量指标。

以后可增加可选的“疑难媒体复核”阶段，只处理用户选择或低置信项目。其输出作为文字说明，不改变删除默认选择。

## 错误处理

- 单个媒体读取失败不终止批次。
- 模型初始化失败将对应阶段标记为可重试失败，并继续运行不依赖该模型的阶段。
- 存储空间不足时暂停新解码，保留已提交断点。
- 中高温状态等待降温，临界温度把当前工作项转为可恢复状态。
- 用户撤销媒体权限后，工作项标记为权限失败，不循环重试。
- 原媒体在分析期间被删除时，清理其可重建缓存和未确认建议。

### 最终真机测试

代码和自动化测试完成后再接入 Redmi K70 Pro，验证：

- 三个模型的 CPU/GPU 延迟、内存和温度。

- 2 小时演唱会视频的断点和温控。
- 动态照片在 HyperOS 相册中的识别和播放。
- 批量删除确认、取消和最近删除恢复。

## 实现顺序

1. 模型清单、下载校验和 assets 加载。
2. Room 批次、工作项和分析结果结构。
3. EfficientNet-Lite2 分类适配器。
4. MobileNetV3 向量持久化与相似扫描。
5. EfficientDet-Lite2 条件检测。
6. 图片批量 Worker。
7. 视频模型管线与逐阶段断点。
8. 推荐引擎和人工确认页。
9. 自动化测试、文档和最终真机验收。
